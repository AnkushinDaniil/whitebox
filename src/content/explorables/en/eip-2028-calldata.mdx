**Istanbul, December 2019.** Some upgrades change what Ethereum *can do*; this one changed what became *economically possible* — and in doing so it quietly started the rollup era. A [rollup](/eip-4844-blobs) scales Ethereum by executing transactions off-chain but publishing their data *on*-chain, so anyone can reconstruct and check the L2. That published data is the rollup's security, and it lives in **calldata**. The catch: calldata was priced at **68 gas per byte**, which made posting data the single biggest cost of running an L2 — expensive enough that rollups barely penciled out. **EIP-2028** is a one-line price change with outsized consequences. Let's derive it.

## The problem: publishing data dominated rollup fees

A rollup's guarantee is <KeyTerm term="data availability" def="The property that a rollup's transaction data is published somewhere anyone can retrieve, so they can independently reconstruct and verify L2 state. Rollups get it by posting compressed batch data to Ethereum L1 as calldata." />: it posts its compressed batch of L2 transactions to L1 so that anyone can rebuild the L2's state and check it. On L1, that batch rides in <KeyTerm term="calldata" def="The input data of a transaction — read-only bytes the EVM can access. It's where rollups put their batch data. Its gas cost is per-byte: originally 68 gas for a non-zero byte, 4 for a zero byte." />, and calldata was billed **68 gas for every non-zero byte**. Since a rollup's whole job is to publish lots of bytes, that per-byte cost dominated everything else — it, not execution, set L2 fees. Rollups were the community's scaling plan, but at 68 gas a byte the numbers barely worked.

<Scene name="cd-cost" caption="A rollup posts its batch of thousands of L2 transactions to L1 as calldata so anyone can verify it — and at 68 gas per non-zero byte, that data was the dominant cost, keeping L2 fees high. Rollups were the scaling plan, but the price of data made them barely viable." />

<Callout type="warning" title="What breaks">
The 68-gas price was a conservative old estimate of what a byte of calldata costs the network to propagate and store. If it was set too high relative to reality, then rollups — the thing that most needs cheap data — were being overcharged for no good reason. The question is whether it *can* safely come down.
</Callout>

## EIP-2028: a non-zero calldata byte drops to 16 gas

Analysis of the real bandwidth and worst-case block-size impact showed 68 was far higher than necessary. EIP-2028 lowered the cost of a **non-zero** calldata byte from **68 to 16 gas** — roughly a **4× reduction** — leaving zero bytes at 4 gas. The reason it's a *balance* and not "make it free": cheaper calldata means a transaction can pack in more bytes for the same gas, so a maliciously data-heavy block could be *larger* and take longer to propagate. `16` was chosen as the point where the worst-case block still propagates safely, while data gets dramatically cheaper for everyone who uses it honestly.

## The payoff: rollups start to add up

With the dominant cost cut roughly fourfold, the rollup math finally worked. **Optimistic rollups** (Arbitrum, Optimism) — which post batch data and rely on fraud proofs — and **zk rollups** (zkSync, Starknet) — which post data plus a [validity proof](/eip-196-197-bn128-precompiles) — became genuinely cheaper than doing the same transactions on L1, and the L2 ecosystem took off. EIP-2028 didn't invent rollups, but it's the repricing that made them *economical*, kicking off Ethereum's rollup-centric scaling roadmap.

<Scene name="cd-rollup" caption="With data ~4× cheaper, optimistic rollups (post data + fraud proofs) and zk rollups (post data + validity proofs) became economical, opening the L2 era. Data was still the bottleneck — which EIP-4844's blobs would later cut much further." />

<Callout type="insight" title="And that is EIP-2028">
A rollup's security is its **published data**, which lives in **calldata** priced at 68 gas/byte — so data was the dominant L2 cost and rollups barely added up → analysis showed 68 was too high, so **cut a non-zero byte to 16** (~4× cheaper), balanced against worst-case block size → and that made **optimistic and zk rollups economical**, launching Ethereum's rollup-centric scaling era. It's a reminder that a single well-chosen constant can unlock a whole ecosystem. And the story continues: data was still a rollup's biggest expense, so [EIP-4844](/eip-4844-blobs) later moved it off calldata entirely into cheap, ephemeral **blobs** — 2028 opened the door; 4844 widened it.
</Callout>
